Complete guide for Inventory, Billing, Accounting, GST, POS, PWA, and Reporting.

This documentation helps administrators, accountants, sales teams, purchase teams, inventory managers, HR users, and developers configure and operate the ERP from installation through production maintenance.

Getting Started

The ERP is organized around core business flows: purchase inventory, sell goods or services, collect payments, manage returns, post accounting entries, generate GST-ready reports, and monitor performance from dashboards.

Recommended rollout: configure company settings first, then taxes, chart of accounts, product categories, suppliers, customers, opening stock, roles, and users.
  1. Install dependencies. Prepare Laravel packages and frontend assets with Composer and npm.
  2. Configure environment. Set database, mail, queue, cache, session, currency, GST, POS, PWA, and application URL values.
  3. Run migrations and seeders. Create tables, permissions, default roles, chart of accounts, and starter settings.
  4. Create admin user. Assign the Super Admin role and verify that the user can access settings.
  5. Test workflows. Create a product, customer, supplier, purchase bill, sales invoice, return, and payment.

Installation & Setup

Run these commands from the project root. Replace repository and domain placeholders with your actual values.

Terminal
git clone https://example.com/your-company/erp-system.git
cd erp-system

composer install --no-dev --optimize-autoloader
npm install
npm run build

cp .env.example .env
php artisan key:generate
php artisan storage:link
Production note: never run production with APP_DEBUG=true. Debug mode can expose stack traces, database names, and server paths.

Database Setup

Create a database and user, then migrate and seed the schema. Seeders should create roles, permissions, settings, units, tax rates, and a starter chart of accounts.

MySQL
CREATE DATABASE erp_database CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'erp_user'@'localhost' IDENTIFIED BY 'replace_with_secure_password';
GRANT ALL PRIVILEGES ON erp_database.* TO 'erp_user'@'localhost';
FLUSH PRIVILEGES;
Laravel
php artisan migrate --force
php artisan db:seed --force
php artisan config:cache
php artisan route:cache
php artisan view:cache

Accounting Workflow

The accounting module centralizes postings from sales, purchases, payments, returns, stock adjustments, and journal entries. It supports general ledger, subsidiary ledgers, trial balance, balance sheet, profit and loss statement, audit trails, and multi-currency transactions.

  1. Configure chart of accounts. Map cash, bank, receivables, payables, sales, purchases, tax, inventory, discount, and expenses.
  2. Post source transactions. Sales create receivables and revenue; purchases create payables and inventory or expense entries.
  3. Track subsidiary ledgers. Customer and supplier ledgers reconcile against control accounts.
  4. Review statements. Generate trial balance first, then profit and loss, then balance sheet.
  5. Use audit trails. Review who created, edited, approved, deleted, or exported records.

GST & Tax Workflow

GST reports depend on company GSTIN, place of supply, customer and supplier tax registration, product HSN/SAC codes, and tax rates. The ERP calculates CGST, SGST, IGST, line tax, document tax totals, and rounding.

GSTR-1

Summarizes outward supplies, invoice details, taxable value, tax amount, credit notes, and debit notes.

GSTR-3B

Provides monthly summaries for outward tax, input tax credit, reverse charge, and payable tax.

Tax Calculations

Supports inclusive or exclusive tax, line-level tax, document-level totals, and rounding adjustments.

Placeholder guidance: exact return formats may change. Validate exported data with your tax consultant or filing portal before submission.

Sales Workflow

Sales starts with customer selection and ends with invoice posting, stock deduction, payment tracking, and receivable reporting. Returns restore stock only after approval.

  1. Select or create a customer profile with GSTIN, billing address, shipping address, credit limit, and terms.
  2. Add invoice items, quantities, discounts, tax rates, batch/serial details, and shipping charges.
  3. Save as draft or post as confirmed invoice to reduce stock and create accounting entries.
  4. Record full or partial payment through cash, bank, UPI, card, cheque, or custom payment mode.
  5. Create sales return for damaged, wrong, or rejected goods. Approved returns restore inventory and adjust receivables.

Purchase Workflow

Purchase management controls vendor bills, tax calculation, inventory receipts, purchase payments, and returns to suppliers. Approved bills increase stock and create payable entries.

  1. Create supplier profile with tax registration, address, bank details, and payment terms.
  2. Create vendor bill with products, quantity, rate, discount, tax, freight, and supplier invoice number.
  3. Post the bill to update inventory and accounting ledgers.
  4. Track payments against the bill and monitor payables aging.
  5. Process purchase return to reduce inventory and adjust supplier balance.

POS Workflow

The POS module is optimized for touch screens, thermal printer support, receipt printing, barcode scanning, barcode generation, barcode printing, quick payments, and counter sales.

  1. Open POS terminal and select warehouse, register, cashier, and price list.
  2. Scan barcode or search by product name, SKU, category, or code.
  3. Apply discount, tax, customer details, and payment mode.
  4. Print thermal receipt and optionally send digital invoice by email or SMS gateway placeholder.
  5. Close shift and reconcile cash, card, UPI, and return transactions.

PWA Setup Guide

The Progressive Web App layer makes the ERP installable on Android, iOS, Windows, and macOS. Offline functionality can cache the application shell and queue supported actions until the internet returns.

PWA checklist
1. Enable HTTPS on production.
2. Create public/manifest.json with app name, icons, theme color, and start URL.
3. Register service worker from the main layout.
4. Cache static assets and critical routes.
5. Store offline POS drafts or syncable records in IndexedDB.
6. Retry sync when navigator.onLine returns true.
7. Test install prompt on Android Chrome, desktop Chrome, and iOS Safari.
Offline warning: accounting postings, invoice numbers, and stock-sensitive operations must sync carefully to avoid duplicate document numbers or incorrect stock.

Deployment Guide

Deploy the ERP with SSL, queue workers, scheduled tasks, restricted file permissions, and optimized Laravel caches. The web server document root must point to the public directory.

Production deployment commands
git pull origin main
composer install --no-dev --optimize-autoloader
npm ci
npm run build

php artisan down
php artisan migrate --force
php artisan optimize:clear
php artisan config:cache
php artisan route:cache
php artisan view:cache
php artisan queue:restart
php artisan up

FAQ

Can the ERP run on shared hosting?

It can run on capable shared hosting if PHP version, extensions, database, cron, storage permissions, and public directory routing are supported. VPS hosting is recommended for queues, scheduled reports, backups, and larger exports.

Does the system support multiple currencies?

Yes. Configure default currency, exchange rates, currency rounding, and posting rules before entering multi-currency transactions.

How are sales returns handled?

A sales return creates a return document, adjusts the customer balance, restores stock after approval, and records accounting entries for revenue and tax reversal where applicable.

Can reports be exported?

Yes. Reports can be exported to Excel, PDF, and CSV. Scheduled delivery can send selected reports to configured recipients using queued jobs.

Is offline POS supported?

Offline POS can be supported with PWA caching and IndexedDB draft storage. Final posting should sync when connectivity returns to preserve invoice numbering, stock accuracy, and accounting integrity.
